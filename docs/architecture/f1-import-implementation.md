# F1 文件导入实现与剩余项

关联 #5。本切片是导入基础设施，不能据此关闭 #5。

## 已实现

- `BridgeDiaryApi` 显式适配 `prepareImport`、`finishImport`、`importStatus`，保留核心错误翻译，能力清单只报实际接通的方法。
- `FileImportCoordinator` 独立于 Widget：申请限域票据、检查已有状态、流式复制、刷盘、提交字节数和 SHA-256 给核心校验。
- 同一个 operationId 并发执行会被拒绝；重试时若核心已是 ready/verifying，不重新复制，不覆盖已接受的文件。
- 每块写入完成才读取下一块；复制内存不随文件大小增长。前提是平台来源提供有界块流（如 File.openRead），不能把整个文件预读成一个大块。
- 取消可以打断等待下一块数据；超限先拒绝该块，不写入超限字节；复制出错或取消后不调用 finishImport，并抛出包含 importId 的 ImportInterrupted。
- 中断的暂存文件留给核心恢复；平台层不自行删除核心票据之外的文件，不把“复制完”展示成“入库成功”。只有核心 ready 才算入库完成。

## 当前限制

- 桥接生成 API 尚未暴露 cancelImport 和录音交接接口，取消复制不等于核心取消成功。不得显示“核心已清理”；当前只保证停止流式复制并保留恢复编号。
- 真实文件选择器、页面服务注册与附件状态展示仍待接入。
- 原生录音前台服务、首缓冲确认、设备切换与封闭片段恢复仍待实现；本切片没有假录音实现。
- MIME 是提示，内容真实性和哈希由核心再次校验。
- 真机长录音与锁屏验收按当前安排暂缓，不能把未验证写成通过。
