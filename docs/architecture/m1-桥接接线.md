# M1 · 桥接接线

对应 issue [#28](https://github.com/xingxue-ux/unwritten-diary/issues/28) · 日期 2026-09-28 · 执行人 xingxue-ux

把 `diary_core` 接到 Dart。代码在 `crates/diary_bridge/src/api.rs` 与 `packages/diary_bridge/`。M0 的探针阶段结论见 [M0-桥接验证](M0-桥接验证.md)。

## 这一片解决了什么

在此之前，四片核心（B1a/B1b/B1c/B2）都只能靠 `cargo test` 自证——前端一行都跑不上。现在 **Dart 能真的调用核心并读写资料库**，而且三个平台都验过。

## 定下的决定

| 决定 | 理由 |
|---|---|
| 桥接层不另造 DTO | `flutter_rust_bridge.yaml` 的 `rust_input` 加上 `diary_core::model`，frb 直接按核心的字段定义生成 Dart 类型。少一套需要同步维护的映射，也不会出现「函数签名与核心字段对不上」 |
| 用不透明会话句柄 `BridgeSession` | 核心是有状态的（一个 SQLite 连接 + 内存里的租约），Dart 侧持有的应该是句柄，而不是每次调用都传一遍路径 |
| 错误统一映射成契约错误码 | `CoreError` → `BridgeError { code, message, retryable }`，`code` 就是契约第 7 节的字符串。前端可以 `on BridgeError catch (e) { switch (e.code) … }` |
| 能力清单写进 `LibraryInfo.capabilities` | **没列出来的就是还没接**。界面据此决定哪些入口可见，而不是点下去才发现没实现 |
| 时间类型走 frb 的 chrono 集成 | 打开 frb 的 `chrono` / `uuid` feature，时间字段直接是 Dart 的 `DateTime`，不用手写字符串转换 |

## 已经接上的契约方法

```
core.open            captures.createDraft    imports.prepare      sources.extract
core.snapshot        captures.saveDraft      imports.finish       sources.extractedContent
core.events          captures.commit         imports.status       sources.locate
                     captures.get            jobs.list            jobs.get
                     captures.list           jobs.nextWakeup
```

**没接的都在清单外**：日记生成、搜索、索引、插件、备份、Provider 配置、录音会话、任务执行等。前端不该把它们显示成可用。

## 验证到了什么

端到端测试 `packages/diary_bridge/test/bridge_probe_test.dart`（6 项）在两个桌面平台跑，Android 上的等价探针 5 项：

| 平台 | 结果 |
|---|---|
| Linux（WSL）宿主 | **6/6** |
| Windows x64 | **6/6** |
| Android（API 36 x86_64 模拟器） | **5/5** |

覆盖的是完整链路，不是「能调通一个函数」：

- 打开资料库 → `schemaVersion = 4`、能力清单、恢复摘要
- 创建草稿 → 保存（`durable = true`）→ 提交 → 重新读出来，字段一致
- **导入一个文本文件**：拿暂存票据 → 写字节 → `finishImport`（核心自己重算哈希）→ 排队 `extract` 任务 → 用任务目标提取 → 两段正文与字符区间正确 → 按来源读派生内容 → 定位原件
- 核心错误映射：查不存在的记录 → `BridgeError.code == "not_found"`、`retryable == false`
- 事件按序号递增，可从游标之后补读
- 中文与 emoji 跨桥往返不变形

## 过程中发现的三件事

1. **Windows 上不关会话就删不掉临时目录**：SQLite 连接还开着时 `deleteSync` 直接抛异常（Linux 允许）。测试里先 `session.dispose()` 再删，并且删除失败不让测试失败。真实应用退出时也要注意这个顺序。
2. **`wire()` 被 frb 镜像成了 `Future<void>`**：核心给枚举加的 `wire()` / `from_wire()` 是给持久化用的，frb 把它们也生成到 Dart，而且返回类型不对。**这属于要清理的瑕疵**——正确做法是把这两个方法从 `impl` 块挪到不参与 codegen 的模块里。现在 Dart 侧不要用它们，直接比较枚举值。
3. **`eventType` 而不是 `type`**：frb 按 Rust 字段名生成，不读 serde 的 `rename`。契约里写的是 `type`，做 Dart 适配层时要做一次改名。

## 没有做到的

- **没有 `diary_api` 适配层**：生成的类型和契约 DTO 形状一致但名字不同（`eventType` vs `type`、枚举名大小写等）。写适配层属于 F0 的活，等前端真的要用时按需做，避免现在凭猜测设计。
- **没有事件订阅**：只有 `events_since` 拉取，没有做成 `Stream`。前端要的是流，这需要在桥接层加 `StreamSink`（M0 已经验证过这条链路可用）。
- **没有长任务的进度与取消**：`jobs` 只能列、看、以及读唤醒时刻。
- **录音会话没接**：`recordings.*` 一个都没接，因为前端平台层还没建。
- **测试里的平台差异只覆盖到模拟器**：arm64 真机仍未验证。
