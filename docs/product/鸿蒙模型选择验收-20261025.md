# 鸿蒙模型选择验收

版本：1.0.2（versionCode 1000002，buildVersion 1）。

此前升级会新增已启用的随包本机整理配置，同时保留已启用的在线服务。
核心一次只选择一个服务，界面却把两个都标成“已启用”。本次改为明确选择一个整理服务。

## 结果

- 通过 `providers.selectGeneration` 在同一数据库事务中切换，其他整理服务停用。
  保存的模型、凭据引用、连接测试结论保持不变，单独的语音转写配置不受影响。
- 全新安装仅默认使用本机整理。旧版双启用状态通过一次性迁移修复，沿用原有测试状态、创建顺序优先级。
- 已配置且连接测试通过的在线服务在卡片上提供“使用此服务”，不再需要进入编辑才能切换。
  当前服务显示“当前使用”，按钮为不可重复点击的“正在使用”。
- 模型列表仍在用户点击查询时从服务端获取。已知模型显示中文简称和原始编号；没有预设简称的新模型直接显示原始名称。
  中文简称使用准确映射，不再根据编号中包含某个词猜测模型类别。请求始终使用原始编号。

## 验证

- 主机：37 项服务核心回归、43 项 C 接口回归、17 项日记生成回归、28 组界面交互与 11 组模型部署回归通过。
  包含切换失败的事务回滚、保留密钥、转写独立、卡片直接切换、升级迁移重试与只执行一次、未知模型名称保留。
- 核心与 C 接口 Clippy 全目标检查无警告；跨端字体、视觉基线检查通过。
- DevEco 完整 ArkTS 编译及原签名 debug / release HAP 构建通过；保留既有 SDK 弃用警告。
- 真机：HAD-W32，HarmonyOS API 23。由 1.0.1 覆盖升级，原有在线服务保持当前使用，本机显示未使用。
  点击本机后在线退出；在深度求索卡片直接切回在线成功，没有进入编辑表单。
- 真机模型查询成功，返回 `deepseek-flash`、`deepseek-v4-pro`，界面分别显示“快速模型（deepseek-flash）”和“专业模型（deepseek-v4-pro）”。
  新模型的原样显示使用主机回归覆盖，未虚构服务端不存在的模型。
- 独立空白测试资料库首次使用：记录为 0 条，仅本机整理显示当前使用，无需在线密钥。
  验收后由应用测试清理入口删除隔离目录；用户主资料库仍有原来的 7 条记录。
