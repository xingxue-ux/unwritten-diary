## 0 先看结论

1. **一级入口只有 5 个，顺序固定**：
   `记录 → 日记 → 搜索 → 片段 → 我的`。
   桌面放顶栏、移动放底部页签都可以；**集合、顺序、名字不能变**。
2. **任务中心不是一级入口**。它从两处进：全局 header 的任务图标、
   「我的 → 创作与整理 → 任务中心」。鸿蒙现在把它做成 tab，是本次要迁掉的最大结构差。
3. **「今日」不是一级入口，也不能直接改名成「日记」**。鸿蒙 `TodayPage` 是
   **原始记录列表**（带转写状态、录音按钮）；Windows 的「日记」是**成篇正文 +
   版本/候选**。把前者改名成后者，tab 检查会绿，但 IA 仍然是错的（见 §9 #2）。
4. **「设置」不是一级入口**。设置分组要放进「我的」；「我的」是个人空间 +
   资料边界 + 创作/整理偏好，不是一张诊断表。
5. **状态词与错误话术逐字一致**。`draft` 的徽标是「草稿」，不是「未提交」；
   `trashed` 是「已移入回收站」，不是「已删除」。完整清单见 §4，现状差异见 §6。
6. **文案表是语义层，不是装饰层**。只收状态词、错误话术、隐私承诺、
   导出/备份警告、危险操作确认；不收「今天，想留住什么？」这类标题。
7. **检查器现在必须红**。`origin/main` 上鸿蒙主壳还没合入，默认跑会以
   `arkts.shell_missing` 失败；拿 PR #150 的 `Index.ets` 跑会以 4 ≠ 5 失败。
   这不是脚本坏了，是红灯本身就是交付物（§8 贴了真实输出）。

## 2 一级入口（5 个，顺序固定）

> 每个入口统一回答三件事：**职责一句话**、**进入后看到什么**、**哪些操作在这里**。
> 「不在这个入口」同样重要：它防止把相邻入口的职责吸过来。

### 2.1 记录（`nav.record`）

- **职责**：新建或续写一条原始记录，并把它收好。
- **进入后看到什么**：
  - 日期（可改）与提示语；文字编辑器；保存状态（未保存 / 保存中 / 已保存 / 失败）。
  - 附件卡片（导入进度、文件信息、处理状态）；录音入口；「收好这一刻」。
  - 桌面宽屏：左侧提示 + 右侧编辑器双栏；移动窄屏：单列。
  - 依据：[`_recordPage`](../../apps/diary_app/lib/src/experience_shell.dart#L991-L1077)、
    [`_saveStatus`](../../apps/diary_app/lib/src/experience_shell.dart#L1197-L1236)。
- **哪些操作在这里**：改日期、输入正文、导入文件为新记录、添加/移除材料、
  开始录音（平台能力就绪时）、自动保存草稿、提交（收好）、失败后重试/复制文字。
- **不在这个入口**：历史时间线（去「片段」）、成篇日记与版本（去「日记」）、
  任务队列（去「任务中心」）。
- **鸿蒙现状**：`TodayPage` 是「列表 + 录音按钮」，没有编辑器/提交；
  迁移时把**列表**移到「片段」，把**录音 + 编辑器**放到「记录」。

### 2.2 日记（`nav.diary`）

- **职责**：按天阅读、整理成篇日记，管理候选版与人工版本。
- **进入后看到什么**：
  - 某一天的成篇正文（自然段优先，不做要点/表格化）；材料覆盖提示；
    正文下方的来源条/来源面板；「整理」「重新整理」「版本」入口。
  - 没有正文但有材料：显示材料与「整理中 / 待配置 / 可以整理」；
    没有材料：自然空白，不编造内容，不制造打卡压力。
  - 版本面板：当前阅读版、整理候选；桌面并排、移动上下；
    采用候选、保留当前、编辑后保存为新版、查看旧版本。
  - 依据：[`_diaryPage`](../../apps/diary_app/lib/src/experience_shell.dart#L1303-L1310)、
    `_versionsPanel`（`:1776` 起）、任务书 §4.4/§4.5。
- **哪些操作在这里**：按天切换、整理/重新整理、查看来源、采用/保留/编辑版本、
  对比版本、查看历史版本。
- **不在这个入口**：原始材料列表（「片段」）、全局搜索（「搜索」）、
  后台任务队列（「任务中心」）。
- **鸿蒙现状**：**缺失**。PR #150 没有任何成篇日记页面；`TodayPage` 的列表不是日记。
  这是本次 P0 缺口，不是「合进今日」就能算完成。

### 2.3 搜索（`nav.search`）

- **职责**：用一个框找回本机的文字与原始材料，并定位到来源。
- **进入后看到什么**：
  - 搜索框、检索模式（关键词 / 语义 / 混合）、材料类型筛选（全部 / 文字 / 录音 / 文件）。
  - 语义索引覆盖提示（`semantic_index_ready=false` 时）；结果卡片（日期、类型、
    摘录、命中方式、覆盖程度）；分页/加载更多；核心 warnings 原样展示。
  - 空结果与「有内容但没处理」分开表达。
  - 依据：[`_coreSearchHeader`](../../apps/diary_app/lib/src/experience_shell.dart#L828-L903)、
    PR #150 `SearchPage.ets`。
- **哪些操作在这里**：输入/提交查询、切换模式、筛选、取消本次搜索、
  升级为混合检索、加载下一页、打开命中详情/来源/当天日记。
- **不在这个入口**：编辑正文、整理日记、管理任务。
- **两端现状**：搜索都存在。Flutter 默认关键词、混合升级取决于
  `supportsHybridUpgrade`；鸿蒙有关键词/语义/混合三模式，但覆盖提示的措辞与
  Windows 不一致（§6.4）。

### 2.4 片段（`nav.snippets`）

- **职责**：原始材料的时间线——保存下来的文字、录音、文件、图片，**不是日记正文**。
- **进入后看到什么**：
  - 「留下的片段」标题；按时间排列的原始记录；每条显示状态徽标（草稿/已提交/回收站）、
    类型、日期、摘录；加载更多；空状态引导去「记录」。
  - 依据：[`_timelineScroll`](../../apps/diary_app/lib/src/experience_shell.dart#L905-L945)、
    [`_timelineHeader`](../../apps/diary_app/lib/src/experience_shell.dart#L1571-L1586)。
- **哪些操作在这里**：打开记录详情、加载更多；（后续可加按天/类型筛选，但不是首版必需）。
- **不在这个入口**：写新记录（「记录」）、读成篇日记（「日记」）、全局检索（「搜索」）。
- **鸿蒙现状**：**缺失**。`TodayPage` 的列表最接近，但它是按天浏览 + 顶部录音，
  需要拆成「片段」的列表语义；不要把它留在「记录」里。

### 2.5 我的（`nav.profile`）

- **职责**：个人空间与设置入口：资料边界、创作/整理偏好、应用与资料管理。
- **进入后看到什么**：
  - 本地资料边界说明（`privacy.local_only`）；最近记录数；两个主要分组：
    - **创作与整理**：风格偏好、模型服务、整理时机、任务中心（二级入口）。
    - **资料与应用**：插件、备份与恢复、阅读导出、存储与回收站、封面与加载动画。
  - 鸿蒙还需保留**设备与诊断**分组：模型状态（语义/转写）、语义索引、队列概览、
    诊断、转写引擎配置。
  - 依据：[`_profilePage`](../../apps/diary_app/lib/src/experience_shell.dart#L1626-L1671)、
    PR #150 `SettingsPage.ets`。
- **哪些操作在这里**：打开上述二级面板/页面；查看本地资料边界；
  进入任务中心；进入备份/导出/回收站。
- **不在这个入口**：不直接展示任务列表、不直接把诊断表当首屏、不把设置项平铺成
  另一个一级 tab。
- **鸿蒙现状**：`SettingsPage` 是一个一级 tab，包含模型、索引、任务概览、诊断；
  迁移时**重组**进「我的」，不是把 tab 改名为「我的」就交差。

### 2.6 tab → 页面映射

| index | Flutter（当前） | 鸿蒙（当前，PR #150） | 鸿蒙（目标） |
|---:|---|---|---|
| 0 | `_recordPage` | `TodayPage`（列表 + 录音） | `RecordPage`（编辑器 + 录音；新建） |
| 1 | `_diaryPage` → `AiDiaryPanel` | `SearchPage` | `DiaryPage`（成篇 + 版本；新建） |
| 2 | `_searchScroll` | `JobsPage` | `SearchPage`（复用） |
| 3 | `_timelineScroll` | `SettingsPage` | `SnippetsPage`（由 `TodayPage` 列表拆出） |
| 4 | `_profilePage` | — | `ProfilePage`（由 `SettingsPage` 重组） |
| 二级 | 任务中心（header + 我的） | 任务 tab | 任务中心（header + 我的） |

> **迁移顺序建议**：先拆 `TodayPage`（列表→片段、录音→记录），再把 `JobsPage`
> 从 tab 移到二级，最后重组 `SettingsPage` 为「我的」并补「日记」。
> 不要先改 tabBar 名字——那只会让检查器变绿，页面职责仍然错位。

**二级页的准入规则**

- **任务中心**：只能从 header 或「我的」进；不能出现在一级 tab 集合里。
- **设置分组**：只能从「我的」进；「我的」不是诊断页。
- **详情/版本/对比**：只能从内容进入（片段/日记/搜索），不能做一级入口。
- **平台能力缺失**（备份、导出、插件、回收站）：可以没有，但不能用假入口冒充；
  鸿蒙设置页现在的「未接的能力」说明是正确做法，迁移时保留这段诚实说明。

## 4 状态与文案语义层

> **这一层是契约，不是建议。** 两端描述的是同一个核心状态/同一类错误；
> 如果措辞不同，用户无法判断哪个是真的。机器可读副本见
> [`ui_strings.json`](../../packages/ui_strings/ui_strings.json)。

### 4.1 三条硬规则

1. **一个语义槽位一个 key**。徽标、错误标题、隐私承诺、危险确认都从表里取；
   不允许 Dart 一份、ArkTS 一份「同义改写」。
2. **状态词只描述状态，不描述操作**。`failed` 的徽标是「未完成」；
   是否可重试由按钮和说明表达，不能把「可重试」写进状态词。
3. **核心给的 `message` / `reason` / `warnings` 原样展示**；
   UI 不按 `error_code` 自己拼用户文案（m6 文档 §9 #11，PR #142）。
   界面自己的标题/建议来自本表；两者不混写。

### 4.2 记录状态（`CaptureState`）

| key | 用户看到 | 含义 | 允许的补充 | 禁止 |
|---|---|---|---|---|
| `state.draft` | **草稿** | 还没提交；可以继续写/提交 | 副标题可写「尚未提交」「finalize 后未提交」 | 把徽标写成「未提交」或「已保存」 |
| `state.committed` | **已提交** | 已进入正式记录；仍可编辑产生新版本 | 无 | 写成「已完成」「已定稿」 |
| `state.trashed` | **已移入回收站** | 离开默认时间线/搜索，可恢复 | 说明「仍可从存储与回收站恢复」 | **「已删除」**——它会被读成不可恢复 |

- `trashed` 是**可逆**状态；真正的永久删除是另一个动作（`danger.purge_confirm`）。
  把 `trashed` 写成「已删除」会直接诱发误清理。
- `draft` 的「未提交」可以作为解释，但不能替代徽标；否则用户会以为
  「草稿」和「未提交」是两个不同状态。

### 4.3 任务状态（`JobState` 9 个 + 1 个聚合）

| key | 用户看到 | 可以给 | 不能给 | 备注 |
|---|---|---|---|---|
| `job.queued` | **排队中** | 取消（`jobs.cancel`） | 重试、去配置 | 可能 `next_attempt_at` 在未来 |
| `job.running` | **处理中** | 取消 | 重试、开始 | 进度只在 `progress` 有依据时显示 |
| `job.succeeded` | **已完成** | 无 | 重试 | 终态 |
| `job.retry_wait` | **等待自动重试** | 无 | 重试（会破坏退避） | 不是失败终态 |
| `job.waiting_configuration` | **需要配置** | 去配置（`attention_key` 以 `job-config:` 开头） | 重试 | 不是失败；不退避 |
| `job.waiting_dependency` | **等待前一步** | 无 | 重试、去配置 | `requires_user_action=false` |
| `job.waiting_network` | **等待网络** | 无 | 重试 | 当前没有写入者；不要为它做界面分支 |
| `job.failed` | **未完成** | 仅当可重试时给「重试」；否则「查看原因」 | 对 `storage_full` / `invalid_state` 给重试 | 终态；是否可重试看核心 |
| `job.cancelled` | **已取消** | 无 | 重试 | 由 `jobs.cancel` 产生 |
| `job.needs_attention` | **需要处理** | 按 `attention_key` 路由 | 把它当 `JobState` 值 | 聚合 = `waiting_configuration` + `failed` |

**四聚合**（任务书 §4.7）：

| 聚合 | 包含 | 说明 |
|---|---|---|
| 处理中 | `queued` + `running` | 不要算成失败 |
| 等待 | `retry_wait` + `waiting_dependency` + `waiting_network` | 自动推进，不是用户要动手 |
| 需要处理 | `waiting_configuration` + `failed` | 用 `attention_key` 决定「去配置」还是「查看原因」 |
| 完成 | `succeeded` | `cancelled` 单独收在「已取消」 |

> 依据：m6 文档 §3.2/§3.3（PR #142）、[`m4-任务调度与补做.md`](../architecture/m4-任务调度与补做.md)、
> 任务书 §4.7。鸿蒙的 `jobStateLabel` 已按这张表实现；
> Windows 的 `ai_diary_panel.dart:343-358` 目前是**句子描述**，不是徽标，见 §6.3。

### 4.4 搜索的部分覆盖（`semantic_index_ready=false`）

**先分清三种情况**：

| 情况 | 结果 | 用户看到的 |
|---|---|---|
| 没有生效代次 / 模型加载失败 / 口径不一致 | **空结果** + warning，不退化关键词（semantic 模式） | 原因 + 重建/去配置入口；不要说「没有内容」 |
| 有生效代次、口径一致、模型可用，但 `embedded_chunks < total_chunks` | **返回已嵌入块的部分结果** + warning | `search.partial_coverage`，保留结果 |
| 空查询 / 真的没有命中 | 空结果，但不是「索引不可用」 | 按「没搜到」展示，不要引导重建 |

- `search.partial_coverage` 的整句是：
  **「语义索引还没有覆盖全部内容，结果可能不全（不是「没有结果」）。」**
- 允许在整句后追加 `已嵌入 X / Y 块` 或核心 `reasons[0]`；
  **不允许**把「部分结果」丢掉、显示成空，或改成「没有结果」。
- 混合模式语义拿不到证据时，显示关键词结果 + warning；
  不要把标签写成「混合结果」。
- 依据：m6 文档 §4.3/§4.7（PR #142）、[`m2-检索会话.md`](../architecture/m2-检索会话.md)、
  PR #150 `SearchPage.ets:254-268`。

### 4.5 错误话术

| key | 用户看到 | 处理后 |
|---|---|---|
| `error.revision_conflict` | **内容已被修改** | 保留用户未提交的输入；展示当前版与待保存内容；不自动覆盖 |
| `error.revision_conflict.hint` | **你读到的是旧版本；刷新后重新查看，再决定是否保存。** | 刷新后由用户决定；不猜 revision |
| `error.invalid_state` | **当前状态不允许这个操作** | 显示真实状态；刷新后按当前状态操作 |
| `error.invalid_state.hint` | **数据可能已在别处更新；刷新后按当前状态操作，不要直接重试。** | 不改数据；不重复同一个调用 |

- **不要**把 `revision_conflict` 的标题写成「记录版本冲突」「这一天的正文刚刚变化了」
  这类各端自造的说法；上下文可以另起一行说明「哪一天/哪条记录」。
- **不要**把用户的文字丢掉，也不要只给「请先复制，再重新打开应用」这一条路；
  契约要求保留可恢复草稿（共享契约 §7、任务书 §4.5）。
- `invalid_state` 不是「稍后重试」：状态没变，重试必失败。
- 核心的 `message` 原样展示；UI 的标题/建议用本表。两者不要互相覆盖。

### 4.6 隐私、导出、备份

| key | 用户看到 | 边界 |
|---|---|---|
| `privacy.local_only` | **日记默认只保存在这台设备上；只有你主动配置的模型服务会收到交给它处理的材料。** | 不登录、不自动同步；备份/导出只写到用户选择的位置 |
| `privacy.ai_egress` | **整理时，材料可能发送到你启用的模型服务；请先确认它们的隐私规则与额度。** | 首次配置/首次整理时说明；不逐条弹窗 |
| `export.contains_private_data` | **导出包包含你的私人内容；请保存到你信任的位置，不要上传到不受控的服务。** | 阅读导出不是完整备份；不能用于恢复 |
| `backup.not_encrypted` | **备份没有加密；请保存到你信任的位置，不要上传到不受控的服务。** | 首版普通归档包；不宣称加密 |

  该服务；也不能写「已加密」——首版备份就是普通 zip。
- 依据：共享契约 §8、[`m5-备份与恢复.md`](../architecture/m5-备份与恢复.md)、
  任务书 §4.8。

## 5 桌面 vs 移动：允许差异与禁止漂移

### 5.1 允许的平台适配

| 维度 | 允许 | 例子/依据 |
|---|---|---|
| 一级导航位置 | 桌面顶栏、移动底部页签；平板/PC 可侧栏 | Flutter `>=850` 用顶栏，否则底部 `_bottomNav`（`:459-491`）；鸿蒙可用 `BarPosition.End` 或平板侧栏 |
| 内容列数 | 宽屏双栏、窄屏单列 | 记录页左提示/右编辑器（`:1055-1077`）；版本对比桌面并排、移动上下 |
| 内容最大宽度 | 两端可不同 | Flutter `maxWidth: 1240/1500`；鸿蒙可全宽 |
| 密度/字号/间距 | 可不同 | 桌面 33/52px 标题 vs 移动 29/42px |
| 交互容器 | 桌面 modal、移动 bottom sheet；hover/tooltip | 同一确认的标题/正文/按钮必须一致 |
| 键盘/指针 | 桌面快捷键、焦点、拖放；移动手势 | 不允许因此改变入口集合 |
| 安全区/返回 | 平台返回手势/标题栏 | 不允许把返回做成不可发现 |

### 5.2 不允许的漂移

| 漂移 | 为什么不允许 | 正确做法 |
|---|---|---|
| 一级入口 4 个 vs 5 个 | 用户在两台设备上找不到同一个目的地 | 集合、顺序、名字固定为 5 |
| `任务` 做一级 tab | 后台任务被提升为内容入口；与产品决定冲突 | 任务中心二级：header + 我的 |
| `今日` 直接改名 `日记` | 原始记录列表 ≠ 成篇日记；tab 对但页面错 | 拆成「片段」列表 + 「日记」成篇页 |
| `设置` 替代 `我的` | 丢失个人空间/资料边界；设置分组无家 | 设置分组放进「我的」 |
| 缺 `片段` 或 `日记` | 一级入口缺失，用户无路可走 | 必须有，哪怕先给空状态/能力说明 |
| 状态词不同（草稿/未提交） | 用户以为这是两个状态 | 用 `ui_strings.json` 的同一个 key |
| `trashed` 写「已删除」 | 用户以为不可恢复，诱发误清理 | 写「已移入回收站」 |
| 错误话术不同 | 用户无法判断哪个是真原因 | 标题/建议用同一 key；核心 message 原样 |
| 隐私承诺不同/缺失 | 用户无法判断数据到底在哪 | `privacy.local_only` 两端一致 |
| 危险确认语义不同 | 一边可逆、一边写成永久，误导 | 用同一 `danger.*` 文案与按钮 |
| 窄屏隐藏入口 | 「移动端简化」变成功能消失 | 可以换位置/收纳，不能删入口 |
| 用平台差异解释文案差异 | 平台差异是布局，不是语义 | 文案差异一律按漂移处理 |

**断点不是契约**：Flutter 用 850px、鸿蒙可以用别的断点；断点两侧的
**入口集合、顺序、名字、状态词**不能变。允许断点不同，不允许 IA 不同。

### 6.4 搜索覆盖

| key | Flutter 现状 | ArkTS 现状 | 判定 |
|---|---|---|---|
| `search.partial_coverage` | 没有自己的整句；把核心 `warnings` 用 ` · ` 拼起来显示（`experience_shell.dart:890-892`）；空结果另写「没有找到匹配内容。尚未处理的材料可能暂时无法检索。」（`:889`） | 「语义索引未完全就绪：已嵌入 X / Y 块。语义/混合模式仍会检索已嵌入的块，**结果可能不全（不是「没有结果」）**。」（`SearchPage.ets:262-263`）；命中卡「覆盖：覆盖不全」（`:327`） | **冲突（措辞/结构不同）** |

> 两端都在努力表达「部分覆盖」，但 Flutter 把这句话完全交给核心 warning，
> 一旦核心没给 warning（或换了措辞），Windows 就没有稳定的 UI 文案。
> 契约要求 `search.partial_coverage` 整句必须由 UI 稳定展示，核心 warning 追加在后面。

### 6.7 计数与结论

| 判定 | 数量 | 具体 |
|---|---:|---|
| 一致 | **3** | `nav.search`、`state.committed`、`job.needs_attention` |
| 字面冲突 | **17** | nav.profile；state.draft；state.trashed；9 个 job 徽标；search.partial_coverage；4 个 error key |
| 单边缺失/功能未落地 | **8** | nav.record、nav.diary、nav.snippets；privacy.local_only、privacy.ai_egress；3 个 danger |
| 两边都缺（表里新增） | **2** | export.contains_private_data、backup.not_encrypted |
| **合计** | **30** | 与 `ui_strings.json` 的 30 个 key 一一对应 |

**最高风险的 6 处**

1. **4 vs 5 入口**：鸿蒙缺「日记」「片段」，多「任务」；这不是「少一个 tab」，
   是两类内容没有入口。
2. **今日 ≠ 日记**：`TodayPage` 是原始记录列表；直接改名会让检查器绿、IA 仍错。
3. **我的 vs 设置**：不是改名，是「个人空间/资料边界」与「诊断表」的角色差。
4. **草稿 vs 未提交**：同一状态两个词；用户会以为状态不同。
5. **已删除 vs 已移入回收站**：最危险的一处；「已删除」会被读成不可恢复。
6. **failed 写成「处理失败，可重试」**：对 `storage_full`/`invalid_state` 是错误承诺；
   用户会反复点重试。

> 另外两处「看起来一样、其实不一样」：
> - `job.needs_attention` 两边都是「需要处理」，但 Flutter 只是分组说明/示例，
>   ArkTS 是真实聚合 chip；字面一致不等于实现一致。
> - `state.committed` 两边都是「已提交」，但 Flutter 只在列表/详情显示，
>   ArkTS 还有「已提交为正式记录」的 toast；toast 是动作结果，不要拿它当状态徽标。

## 7 `ui_strings.json` 与接入方式

### 7.1 位置与形状

- 文件：[`packages/ui_strings/ui_strings.json`](../../packages/ui_strings/ui_strings.json)
- 形状：**扁平 JSON**，`key -> 非空字符串`；不嵌套、不注释、UTF-8、LF。
- 为什么扁平：Dart 的 `Map<String, String>`、ArkTS 的 `Record<string, string>`
  都能直接读；检查器也只做一层查找，不让「文案表的结构」变成第三套契约。
- 只收语义层：状态词、错误话术、隐私承诺、导出/备份警告、危险确认、导航名。
  **不收**「今天，想留住什么？」「给今天留一页」这类装饰性标题。

### 7.2 Dart / Flutter 侧

**推荐（不复制文件）**：把 `packages/ui_strings` 做成一个只含 asset 的 Flutter 包：

```yaml
# packages/ui_strings/pubspec.yaml（示例；本次不接线，故未创建）
name: ui_strings
publish_to: none
environment:
  sdk: ">=3.9.0 <4.0.0"
flutter:
  assets:
    - ui_strings.json
```

`apps/diary_app/pubspec.yaml` 加 path 依赖后：

```dart
import 'dart:convert';
import 'package:flutter/services.dart' show rootBundle;

Future<Map<String, String>> loadUiStrings() async {
  final raw = await rootBundle.loadString('packages/ui_strings/ui_strings.json');
  return (jsonDecode(raw) as Map<String, dynamic>).cast<String, String>();
}
```

**备选**：构建时把 JSON 复制到 `apps/diary_app/assets/ui_strings.json`，
用 `rootBundle.loadString('assets/ui_strings.json')`；复制脚本必须保证
**源仍然是 `packages/ui_strings/ui_strings.json`**，不能在 app 里手改。

- 纯 Dart 测试（`packages/diary_api`）不要用 `rootBundle`：
  直接 `File('packages/ui_strings/ui_strings.json').readAsString()`（工作目录为仓库根）。
- 读取失败时：**不要静默回退到各端硬编码文案**；至少打日志/显示诊断，
  否则又会退回两套文案。

### 7.3 ArkTS / 鸿蒙侧

1. 构建时把 `packages/ui_strings/ui_strings.json` 复制到
   `apps/ohos-diary-core/entry/src/main/resources/rawfile/ui_strings.json`
   （或建立等价的构建期链接；**不要在两处手改**）。
2. 用 `resourceManager.getRawFileContent` 读取：

```ts
import { common } from '@kit.AbilityKit';
import { util } from '@kit.ArkTS';

export async function loadUiStrings(): Promise<Record<string, string>> {
  const context = getContext(this) as common.UIAbilityContext;
  const bytes = await context.resourceManager.getRawFileContent('ui_strings.json');
  const text = util.TextDecoder.create('utf-8').decodeToString(bytes);
  return JSON.parse(text) as Record<string, string>;
}
```

- rawfile 文件名大小写敏感；保持 `ui_strings.json`。
- 当前 PR #150 的页面没有读表；本次**不接线**，所以检查器的「源码引用」是 0
  （§8）。接线后检查器会自动检查代码里引用的 key 是否存在。

### 7.4 单一事实源

- 改文案的顺序：**改契约 §4 → 改 `ui_strings.json` → 改两端代码 → 跑检查器**。
- 不允许只改 JSON 不改契约，也不允许只改一端。
- 未来多语言不在本次范围；如果要做，key 不变、值按 locale 分文件，不要给 key 加语言后缀。

## 8 检查器 `tools/check_ui_parity.py`

### 8.1 它检查什么

1. **Flutter 一级导航**：解析 `experience_shell.dart` 里的
   `_navItem(索引, icon, '标签')`，并额外检查桌面顶栏那份硬编码列表
   （`:572-577`）与 `_navItem` 是否一致。
2. **ArkTS 一级导航**：解析 `Index.ets` 的
   `TabContent() { ... }.tabBar('标签')`，按出现顺序取入口。
3. **两端与契约一致**：默认期望是 §2 的 5 个入口；数量、集合、顺序都要对。
4. **文案 key 齐全**：`ui_strings.json` 必须是扁平 `key -> 非空字符串`；
   §4.8 的 30 个 key 中，必需 key 一个不能少。
5. **源码引用**：扫描 `uiStrings.get('...')` / `uiStrings.t('...')` /
   `uiString('...')`；引用了表里没有的 key ⇒ 红。当前两端都没接表，所以引用数是 0；
   这是**已知的检查盲区**，接线后自动生效。
6. **`--json`**：只输出机器可读 JSON；退出码仍然是 0/1。

### 8.2 用法


### 9.2 本契约新增的 IA / 文案规则

| # | DO / DON'T | 后果 | 做法 | 出处 |
|---:|---|---|---|---|
| 1 | **DON'T** 把任务中心做成一级 tab | 后台任务被当成内容入口；4 vs 5 漂移；用户在两台设备上找不到同一个「任务」位置 | 任务中心只从 header 与「我的 → 创作与整理」进 | 产品决定；Flutter `:603-606`、`:1660` |
| 2 | **DON'T** 把「今日」改名成「日记」就交差 | 检查器绿，但「原始记录列表」被当成「成篇正文」；用户看不到日记版本/候选 | 拆：列表→片段，录音/编辑→记录，成篇→日记（§2.6） | PR #150 `TodayPage.ets`；Flutter `_diaryPage` |
| 3 | **DON'T** 用「设置」替代「我的」 | 丢失个人空间/资料边界；设置分组无家；隐私承诺无处安放 | 「我的」保留分组；诊断作为其中一个分组 | Flutter `_profilePage`；PR #150 `SettingsPage.ets` |
| 4 | **DON'T** 给 `trashed` 写「已删除」 | 用户以为不可恢复，可能直接永久清理 | 写「已移入回收站」；永久删除只在 `danger.purge_confirm` 出现 | `AppRuntime.ets:109-110`；§4.2 |
| 5 | **DO** 两端用同一个状态词（draft=草稿） | 「草稿」/「未提交」并存会让用户以为是两个状态 | 徽标取表；「未提交」只能做副标题 | `experience_shell.dart:933` vs `AppRuntime.ets:102-104` |
| 6 | **DON'T** 把 `failed` 一律写成「可重试」 | `storage_full`/`invalid_state` 重试必失败；用户会反复点 | 徽标「未完成」；重试按钮只在核心允许时出现 | §4.3；m6 §9 #10 |
| 7 | **DO** 部分覆盖时保留结果并显示 `search.partial_coverage` | 丢掉有效结果 = 用户以为没搜到；重建引导也会误导 | 结果照常显示，整句 + 核心 warning 追加 | §4.4；m6 §9 #17 |
| 8 | **DON'T** 用「没有结果」覆盖「部分覆盖」 | 用户会停止查找，或以为索引坏了 | 区分「空结果」与「覆盖不全」；空结果才说没找到 | §4.4；PR #150 `SearchPage.ets:262-263` |
| 9 | **DO** `revision_conflict` 保留输入并展示当前版 | 丢文字是最不可接受的失败；「复制后重开」不是正常恢复 | 保留草稿 + 当前版对比 + 用户决定 | §4.5；共享契约 §7 |
| 10 | **DON'T** 让 UI 自己拼核心错误文案 | 核心加/改码时两端漂移；用户看到两套解释 | UI 只取本表标题/建议；核心 `message` 原样 | m6 §9 #11；§4.5 |
| 11 | **DO** 把一级入口名也放进 `ui_strings.json` | 否则检查器只能比中文字面量，改 key 时抓不到 | `nav.*` 5 个 key；检查器校验值 | §7；`check_ui_parity.py` |
| 12 | **DON'T** 在窄屏隐藏一级入口 | 「移动端简化」会变成功能消失；用户无路可走 | 换位置/收纳/更多菜单可以，集合不能少 | §5.2；Flutter `>=850` 断点 |
| 13 | **DO** 用平台差异解释布局，不用来解释文案 | 一旦允许「鸿蒙就叫设置」，状态词也会开始漂 | 布局可不同；§4 的 key 必须逐字一致 | §5 |
| 14 | **DON'T** 让 `--expect` / 检查器变成放行开关 | 会把「4 入口」合法化；红灯失去意义 | `--expect` 只换基准；不匹配仍然非零；CI 不用 `continue-on-error` | §8；仓库 CI 纪律 |
| 15 | **DO** 新增一级入口前先改契约 + 表 + 检查器 | 先写代码再补契约，必然漂移；评审也无法判断对错 | 三处一起改；PR 里贴检查器红/绿 | §7.4；§8 |

## 10 待确认与已知限制

1. **PR #150 未合入**：本文的 4 入口事实来自其 head `641c965`；合入/改写后行号会变，
   结论（4 vs 5、任务一级、缺日记/片段、设置 vs 我的）不变。
2. **鸿蒙的「日记」「片段」页面还不存在**：本契约只定 IA 与文案，不实现页面；
   迁移需要新页面/组件，不能靠改 tabBar 名字完成。
3. **C ABI 能力缺口**：`backups.*`、`exports.*`、`captures.trash/restore/purge`、
   `imports.*`、`plugins.*` 仍未接（见 `crates/diary_capi/src/methods.rs` 头注释）。
   两端在这些入口上应显示「未接/等待核心」，不能用假按钮冒充。
4. **文案表还没接线**：两端都没有读 `ui_strings.json`；检查器的源码引用扫描目前是 0。
   这是有意的下一步，不在本 PR 里改代码。
5. **CI 已验证「会红」，还没验证「会绿」**：PR #156 的 `docs` job 已实跑，
   自测 4/4 通过、真实检查按预期红（§8.4）；转绿要等 PR #150 改成 5 入口并合入。
6. **检查器不能证明页面职责**：它只守 tab 名/顺序/集合与 key；「记录 tab 打开 JobsPage」
   这种错它抓不到。需要人工按 §2.6 评审，或后续加「tab index → 页面组件名」的映射检查。
7. **`--expect` 的语义**：它是「换比较基准」，不是「允许失败」。如果有人用它把 CI
   调绿，等于把契约改成了 4 入口；评审应拒绝。
