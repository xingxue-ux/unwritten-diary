# 鸿蒙首次使用验收（2026-10-24）

本轮在 HAD-W32 / arm64 / API 23 真机上，从空白资料库走产品界面，修复后完成了记录、模型配置、生成、检索和导出主流程。不是只执行后端探针。

## 发现并修复的问题

- 模型服务列表按固定 ID 复用节点，测试与启停后仍显示旧状态。节点标识现在包含显示字段，真机确认状态即时更新。
- 点击“编辑配置”时，程序回填输入框也触发 `onChange`，被误判为未保存修改，阻止连接测试。仅在输入值实际变化时标记修改；重启后直接编辑和测试通过。
- 预设与操作按钮纵向堆叠，结果在页面顶端，首次配置需要来回滚动。改为可换行的紧凑操作区，并将结果放在表单按钮旁。
- 任务统计通过 Builder 的值参数传递，列表已经完成时数字仍停留在旧状态。改为带 `@Prop` 的组件；同一页面取消任务后“需要处理”从 1 更新为 0。
- 等待配置任务恢复后，日记页仍保留上次运行的等待提示。确认队列状态已恢复后清除旧提示，保留真实正文与候选版本。
- 搜索的索引准备入口只打开“我的”，还需再次找诊断区。现在直接进入“搜索索引”，可立即执行首次索引构建。

## 隔离与覆盖边界

未卸载应用、清库或导出原用户资料库。debug 的 `first_run_ui` 使用 `files/first-run-ui/<qa_session>`，由正常产品界面调用相同核心 API；录音、转写设置和模型部署均跟随该目录。普通启动与 release 始终使用原资料库。会话名仅允许小写字母、数字和连字符；无效参数不启动测试，不回退写入原库。

`first_run_asr` 复用相同隔离目录和随包部署，执行现有 WAV 注入验收；`first_run_cleanup` 只删除已选定的 debug 测试目录，禁止删除原资料库。release 不执行这些测试入口。

真实模型调用使用用户授权的测试凭据和虚构材料。密钥未写入代码、报告或安装包，未上传原用户日记。两个最终 HAP 均逐文件扫描，未发现该测试密钥。

本轮保留了设备原有麦克风授权，未重测首次系统授权弹窗；未做断网、错误密钥或锁屏长时间录音回归。首次语义检索仍需显式准备本地索引，入口已直接可达。本轮结果只覆盖上述主流程，不代表尚未接入的完整备份、插件等功能已完成。
