# 鸿蒙随包本地模型

2026-10-25 起，产品 HAP 随包携带转写、语义检索和日记整理模型；在线 LLM 为可选项。

| 能力 | 随包运行文件 | 原始大小 |
|---|---|---:|
| SenseVoice Small INT8 转写 | `model.int8.onnx`、`tokens.txt` | 239,549,735 字节 |
| BGE Small Chinese v1.5 语义检索 | `model_quantized.onnx`、`tokenizer.json` | 24,269,334 字节 |
| Qwen3.5-0.8B Q4_0 日记整理 | `model.gguf` | 563,036,064 字节 |

共 826,855,133 字节（约 788.55 MiB）。只带量化运行文件，不带训练文件或视觉投影模型。
三份固定模型清单是大小、哈希的唯一来源：
[`SenseVoice`](../../models/manifest/sense-voice-small-int8-2024-07-17.json)、
[`BGE`](../../models/manifest/bge-small-zh-v1.5.json)、
[`Qwen`](../../models/manifest/qwen3.5-0.8b-q4_0.json)。模型许可和来源说明也进入 HAP。

## 构建

在仓库根目录运行：

```sh
python tools/stage_ohos_models.py --asr-dir /path/to/sense-voice --bge-dir models/bge-small-zh-v1.5-ours --llm-dir models/llm/qwen3.5-0.8b-q4_0
python tools/stage_ohos_models.py --check
```

脚本校验全部源文件后才开始复制，生成 `resources/rawfile/bundled_models/` 及运行清单。
权重和生成目录不进入 Git；Git 保存清单、准备脚本、许可与运行时代码。
HAP 构建脚本强制检查准备结果，缺模型或哈希不符时失败。

正常产品包默认包含三套模型及其引擎：
`libsherpa-onnx-c-api.so`、sherpa 的 `libonnxruntime.so`（1.16.3），
以及独立命名的 `libonnxruntime-diary-1.29.1.so`（语义检索）、`libdiary_llm.so`（通用文字生成）
和 `libdiary_llm_dotprod.so`（ARM 加速文字生成）。运行时根据系统报告的 CPU 能力选择实现。
先执行 `build-native.sh`、`stage-sherpa.sh`、`stage-ort-1291.sh`、`build-llm.sh`。
本机生成固定使用 llama.cpp `71255fefc092b0344f2acddb891388814ae961be`，
`build-llm.sh` 仅对 OHOS 的线程亲和性接口做兼容补丁，以优化的 CPU 模式构建。
首次下载源代码需要联网；安装后的推理不联网、不启动外部进程。
`SKIP_ASR_LIBS=1` 仍仅供引擎缺失诊断，不能作为离线产品包交付。

## 首次启动

产品先显示纸色的模型准备页，在核心开库前完成以下步骤：

1. 从 HAP rawfile 以 1 MiB 缓冲区异步读取，写入沙箱 `bundled-models/v1/`。
2. 每个文件核对大小、SHA-256，fsync 后原子替换 `.part`；中断和校验失败不覆盖旧文件。
3. 对 `core-config.json` 仅补缺失的语义路径，保留已有字段、snake_case 别名与自定义路径；格式错误时不重写。
4. 没有既有本机转写选择时，通过既有 `providers.*` API 保存内建转写服务的覆盖配置，
   真正执行本地静音推理并确认状态，不发网络请求；已有选择及停用状态保持原样。
5. 单独保存「本机整理」默认服务，不索取密钥，也不在启动时预热生成模型。
   独立完成标记支持旧版升级，并保留之后的停用、移除或自定义模型选择。
6. 之后重启校验并复用模型，不重新创建用户移除或停用的服务。

已安装设备原有的 `asr/sense-voice/`、`models/` 及自定义配置不会被删除。
ASR 默认通过 provider 指定，不注入高优先级 `asrModelDir`，用户之后修改模型目录仍能生效。
配置准备失败时可以重试，或先进入文字记录。准备页不显示虚假的模型可用状态。

## 验证

```sh
python tools/test_stage_ohos_models.py
node tools/test_ohos_bundled_models.cjs
```

六项准备脚本自测覆盖源文件损坏、输出损坏、缺许可、非法路径与额外模型混入。
八组部署回归覆盖首次安装、HAP 内非零偏移、多次分块读取、短写、重启复用、
自定义配置、停用状态、写入中断、资源损坏、错误配置及本机推理失败后重试。
它们不能代替 HAP 编译或设备测试。

debug 专用 `verify_mode=bundled_models` 在新的隔离目录中执行相同部署代码，
验证空配置初始化、ASR 实际推理、语义实际推理及再次启动；不读取或导出用户日记库。
release 门控禁用该入口。

debug 专用 `verify_mode=local_llm` 在全新隔离资料库中部署三类模型，
用四段虚构记录执行产品的保存、生成、队列和版本读取流程，输出正文、耗时、内存与模型来源。
测试断言原文保留和本机服务来源，正文是否忠于材料仍需人工检查。
生成遵循模型自带的非思考模板；令牌或 120 秒运行上限到达时报告失败，不将截断正文冒充完成。

本机日记使用简短的校对指令，分批处理长材料，不让轻量模型承担来源标识解析与多步事实提炼。
原文、快照和来源关联保留。生成结果经过保守的字符、长度、数字、否定词和编辑距离检查；
明显扩写或改动过大时保留该批原文，并在 `generation_options.keptOriginal` 记录处理方式。
这是降低误改风险的启发式检查，不是事实正确性的保证。在线服务沿用原生成流程和风格能力。

### 2026-10-25 本机整理实测

- Qwen3.5-0.8B Q4_0 的来源版本、563,036,064 字节大小和 SHA-256 已固定；权重不进入 Git。
- 185 项核心回归通过（3 项需额外模型的用例跳过），Clippy 无警告；7 项准备脚本、
  9 组部署回归、28 组界面交互及跨端视觉基线通过。
- debug/release 完整 ArkTS 编译和原签名打包通过；HAP 内的 GGUF 哈希与清单一致，
  使用不压缩存储以支持首次启动分块部署。安装包约 889 MB。
- HAD-W32 / API 23：空配置部署后无需密钥即可生成。四段虚构记录分别用时
  1,336 / 631 / 854 / 638 ms，包含首轮模型加载；完整原句保留，无标点的输入补齐标点。
  四次 `keptOriginal=false`，没有通过回退掩盖这组样例的模型结果。
- 此轮为短文本验收，不代表长篇材料或复杂风格也有相同质量和延迟。
  同进程加载转写与生成后，测试进程 PSS 约 1.7–2.1 GiB。
- 首次使用界面显示「本机整理／已启用」，停用按钮可点并真实更新状态。
  测试资料库使用独立目录，已清理；未导出或清空用户原有资料库。
