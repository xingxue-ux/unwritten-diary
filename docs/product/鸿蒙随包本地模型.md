# 鸿蒙随包本地模型

2026-10-25 起，产品 HAP 随包携带**转写**与**语义检索**两组本地模型。

同日后续改版按产品决定**移除随包的日记生成模型**（Qwen3.5-0.8B Q4_0 与 llama.cpp 桥）：
日记生成完全交给用户在「我的 → 模型服务」里配置的在线服务；转写与语义检索仍是本地能力，
不需要网络、也不需要密钥。

| 能力 | 随包运行文件 | 原始大小 |
|---|---|---:|
| SenseVoice Small INT8 转写 | `model.int8.onnx`、`tokens.txt` | 239,549,735 字节 |
| BGE Small Chinese v1.5 语义检索 | `model_quantized.onnx`、`tokenizer.json` | 24,269,334 字节 |

共 263,819,069 字节（约 251.6 MiB）。只带量化运行文件，不带训练文件或视觉投影模型。
两份固定模型清单是大小、哈希的唯一来源：
[`SenseVoice`](../../models/manifest/sense-voice-small-int8-2024-07-17.json)、
[`BGE`](../../models/manifest/bge-small-zh-v1.5.json)。模型许可和来源说明也进入 HAP。

## 构建

在仓库根目录运行：

```sh
python tools/stage_ohos_models.py --asr-dir /path/to/sense-voice --bge-dir models/bge-small-zh-v1.5-ours
python tools/stage_ohos_models.py --check
```

脚本校验全部源文件后才开始复制，生成 `resources/rawfile/bundled_models/` 及运行清单。
权重和生成目录不进入 Git；Git 保存清单、准备脚本、许可与运行时代码。
HAP 构建脚本强制检查准备结果，缺模型或哈希不符时失败。
`--check` 也会拒绝残留的 `llm/` 组：旧版的 563 MB 权重不能跟着新包继续构建。

正常产品包默认包含两组本地能力及其引擎：
`libsherpa-onnx-c-api.so`、sherpa 的 `libonnxruntime.so`（1.16.3），
以及独立命名的 `libonnxruntime-diary-1.29.1.so`（语义检索）。
先执行 `build-native.sh`、`stage-sherpa.sh`、`stage-ort-1291.sh`。
**不再有** `build-llm.sh`、`libdiary_llm.so`、`libdiary_llm_dotprod.so` 与 `diary_llm.cpp`。
`SKIP_ASR_LIBS=1` 仍仅供引擎缺失诊断，不能作为离线产品包交付。

## 首次启动

产品先显示纸色的模型准备页，在核心开库前完成以下步骤：

1. 从 HAP rawfile 以 1 MiB 缓冲区异步读取，写入沙箱 `bundled-models/v1/`。
2. 每个文件核对大小、SHA-256，fsync 后原子替换 `.part`；中断和校验失败不覆盖旧文件。
3. 对 `core-config.json` 仅补缺失的语义路径，保留已有字段、snake_case 别名与自定义路径；格式错误时不重写。
4. 没有既有本机转写选择时，通过既有 `providers.*` API 保存内建转写服务的覆盖配置，
   真正执行本地静音推理并确认状态，不发网络请求；已有选择及停用状态保持原样。
5. **回收旧版本机整理的权重**（一次性标记 `legacy-local-llm-model-cleaned-v1.json`）：
   只删沙箱里的 `bundled-models/v1/llm/`（约 563 MB），升级用户因此拿回这部分空间。
   库里那条 `adapter_id = llama_cpp` 的 `builtin_local_llm` **保留不动**：升级不该让
   配置凭空消失。它会在「模型服务」页单独列为「旧版本留下的配置 / 已不再支持」，
   由用户自己点删除；启动流程不替用户删配置。
   清理失败不阻断启动，下次启动重试；在线服务配置、密钥与日记一个字都不动。
6. 用独立的一次性标记修复旧版双启用状态：在剩下的在线服务里按原有测试状态与创建顺序
   保留一个，其余停用。不会联网、不会重新测试。
7. 之后重启校验并复用模型，不重新创建用户移除或停用的服务。

已安装设备原有的 `asr/sense-voice/`、`models/` 及自定义配置不会被删除。
ASR 默认通过 provider 指定，不注入高优先级 `asrModelDir`，用户之后修改模型目录仍能生效。
配置准备失败时可以重试，或先进入文字记录。准备页不显示虚假的模型可用状态。
准备页文案明确写「整理日记需要配置一个在线模型服务」，不再宣称整理可离线使用。

## 没有在线服务时的产品行为

- 日记页点「整理这一天」**不会**排一条注定卡在 `waiting_configuration` 的任务；
  页面直接显示「整理日记需要一个在线模型服务」，并给「去配置模型服务」按钮。
- 能力闸门与队列仍保留原来的兜底：自动整理/计划任务在等配置时停在
  `waiting_configuration`，`attention_key` 可深链到配置页；这不是生成失败。
- 语音转写与语义检索不受影响，继续使用随包模型。

## 验证

```sh
python tools/test_stage_ohos_models.py
node tools/test_ohos_bundled_models.cjs
```

七项准备脚本自测覆盖源文件损坏、输出损坏、缺许可、非法路径、额外模型混入，
以及**旧版 `llm/` 组残留必须被拒绝**。
十一组部署回归覆盖首次安装（4 个文件、无 generate_text 种入）、HAP 内非零偏移、
多次分块读取、短写、重启复用、自定义配置、停用状态、写入中断、资源损坏、
错误配置、本机推理失败后重试，以及**升级清理本机整理配置行与旧模型目录**。
它们不能代替 HAP 编译或设备测试。

debug 专用 `verify_mode=bundled_models` 在新的隔离目录中执行相同部署代码，
验证空配置初始化、ASR 实际推理、语义实际推理及再次启动；不读取或导出用户日记库。
release 门控禁用该入口。原来的 `verify_mode=local_llm` 探针已随本机整理一起删除。

### 2026-10-25 移除本机整理（本版）

- 删除 `provider/local_llm.rs`（298 行）、`Adapter::LocalLlm`、`cpp/diary_llm.cpp`、
  `build-llm.sh`、Qwen 清单/许可与 `tools/stage_ohos_models.py` 的 llm 组。
- 日记生成只走 `plan_generation`（整篇或两步中间提炼）；`conservative_edit`、
  `localPolicy` 与 `keptOriginal` 元数据随本机路径一起消失。
- **旧版本读回来的兼容**：历史版本的 `generationInfo.generationOptions` 里可能还有
  `keptOriginal` / `localPolicy`。读取侧只是把它当普通键值展示/忽略，字段消失不会报错；
  回归测试直接读一个带 `keptOriginal` 的旧资料库。
- **旧版本配置行的兼容**：`adapter_id = llama_cpp` 的那条 provider 行不静默删除、
  不假装可用。`providers.list` 照常列出；`providers.selectGeneration` 与
  `providers.test` 明确说「旧版本的本机整理，已不再提供，请改用在线服务」；
  `diary.generate` 的任务停在 `waiting_configuration`（不崩溃、不消耗尝试次数、
  不写空正文），`diary.getDay` 照常可读。C ABI 回归直接造一条这样的行来验。
- 版本号升到 1.0.3 / 1000003：这是**功能回退**（新装必须配在线服务才能生成日记），
  用新版本号让升级路径与商店记录可区分。

### 2026-10-25 本机整理实测（历史，功能已移除）

- Qwen3.5-0.8B Q4_0 的来源版本、563,036,064 字节大小和 SHA-256 曾固定；权重不进入 Git。
- HAD-W32 / API 23：空配置部署后无需密钥即可生成。四段虚构记录分别用时
  1,336 / 631 / 854 / 638 ms，包含首轮模型加载；完整原句保留，无标点的输入补齐标点。
- 同进程加载转写与生成后，测试进程 PSS 约 1.7–2.1 GiB；安装包约 889 MB。
  移除后安装包约 326 MB，生成不再占用进程内存。
- 该结论只说明「当时那个本机路径能跑」，不代表现在还有这条路；保留它是为了解释
  为什么移除后需要在线服务，以及 563 MB 体积的来源。

### 2026-10-24 实测（历史）

- 6 项模型准备脚本自测、8 组部署回归、原有 6 组交互回归均通过。
- 两包中的模型逐项核对了字节数与 SHA-256，rawfile 使用不压缩存储以支持分块读取。
- HAD-W32 / API 23：debug 在全新隔离目录中完成模型部署、本机静音转写推理、
  两条虚构材料的语义索引与语义命中、再次准备时复用模型，返回
  `freshInstall=true asrInference=true semanticInference=true restart=true isolated=true`。
- 含模型 release 已覆盖安装原应用，产品启动完成；沙箱中模型哈希与清单逐项一致。
  产品转写设置页执行连接测试，返回真实调用为是、`transcribe_audio: ok`。
