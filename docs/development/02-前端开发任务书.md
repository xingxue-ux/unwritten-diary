# 前端开发任务书

执行前阅读《00-开发总览》《01-共享接口契约》《04-验收与测试计划》。本任务负责 Flutter 应用和 Windows/Android 平台适配；不要实现第二套数据库、模型服务或索引。

## 1. 交付目标

交付一个可实际安装、输入、录音、导入、阅读、搜索和设置的 Windows/Android 客户端。开发期间可以接 Mock，发布验收必须接真实核心。用户无需了解向量模型、任务队列或数据库，也能知道内容是否保存、哪些内容尚未处理。

首屏体验优先于完整首页加载。用户打开应用后，应立即获得可用的记录区域。系统权限首次询问、文件选择器和真实麦克风准备应诚实呈现状态，不用虚假的动画掩盖不可用。

## 2. 模块边界

前端负责 apps/diary_app、packages/platform_host、packages/diary_mock 和 tests/e2e。后端提供 packages/diary_api 和 packages/diary_bridge，前端只依赖公开接口。所有页面通过可注入的 DiaryApi 调用核心；切换 Mock/真实实现不修改页面逻辑。

建议页面状态采用一个统一、明确的方案即可，例如 Riverpod 或同等能力工具；在 M0 冻结依赖，不同时引入多个状态管理框架。后台计算与大文件复制不在 Flutter 界面线程执行。

UI 中的“已保存”由 durable 确认驱动；任务百分比只有核心或原生层有依据时才显示。页面不自行推断 AI 已处理全部材料，不自行生成日归属和版本冲突处理结果。

## 3. 信息架构

| 页面/区域 | 核心用途 | 入口 |
|---|---|---|
| 记录页 | 文字输入、录音、附件；当前草稿 | 默认启动页 |
| 日记页 | 按日期回看自然段正文及关联原件 | 主导航 |
| 搜索页 | 一个框搜索日记和所有材料，筛选及定位 | 主导航、桌面快捷键 |
| 记录详情 | 查看/追加原始材料，查看处理状态 | 时间线、来源面板、搜索结果 |
| 版本页/面板 | 对比、采用、编辑和合并版本 | 日记正文菜单 |
| 任务中心 | 整理、转写、解析、索引状态 | 非侵入状态入口 |
| 设置 | 模型、风格、整理时机、存储与备份、插件 | 主导航次级入口 |

Android 使用适合单手操作的底部主要入口；Windows 使用紧凑侧栏或顶栏与可调整内容区。两端保持信息含义一致，不机械复刻尺寸。窄窗口不能出现被遮挡的保存按钮或无法退出的面板。

## 4. 关键页面详细要求

### 4.1 记录页

首屏保留文字输入区、录音按钮和附件入口。首页不要求填写标题、心情、标签或选择短记/长记模式。日期自动设置，用户可以改。

文字变化后自动保存草稿，建议 300–500 毫秒防抖；焦点离开、应用进入后台、用户提交时立即尝试刷入核心。尚未持久化显示“正在保存”，成功后显示轻量“已保存”，失败保持文本可编辑并提供恢复入口。不要每次自动保存弹 Toast。

桌面 Ctrl+Enter 可提交，Enter 正常换行；中文输入法候选确认期间不能误触提交。Android 软键盘提交动作不应意外结束长文本。用户主动点击完成后可以返回空输入状态，上一条记录仍可快速找到。

附件展示为按添加顺序排列的小卡片，分别显示导入进度、文件信息和处理状态。选择大文件后用户仍可输入文字和添加其他材料。取消一个附件导入不取消整条记录。卡片上的“删除”含义要区分移出草稿与永久删除原件。

冷启动遇到未完成草稿时恢复文本与附件引用；不要强制弹窗询问才能继续。恢复出的中断录音用可展开提示呈现，不把用户锁在恢复流程里。

### 4.2 录音体验

同一个录音入口支持几秒和长时间倾诉。点按开始，支持暂停、继续、结束；不要求长按。安静停顿不自动结束。初版不提供自动插话或默认 AI 陪聊。

状态必须区分“正在准备”“正在录音”“已暂停”“已中断”“正在保存”“已保存”。首个有效音频缓冲到达后才进入正在录音状态。计时来自原生会话，不通过页面本地定时器推断真实录制时长。

提供轻量输入电平或波形，但不为波形高频写库。转写可以延后，录音过程中默认不显示不断改写的实时转写文字。当前页面关闭后录音状态仍可查询。

结束后立即呈现已保存片段和最终化状态；转写、生成向量和 AI 整理独立进行。用户无须等待这些任务完成即可离开。

在 Android 上，由平台层实现必要的录音前台服务及持续通知，用户从前台明确启动录音，处理录音权限、通知行为、来电/音频焦点变化、耳机切换和锁屏。不能依赖 Dart 页面存活来持续保存声音。[Android 麦克风前台服务要求](https://developer.android.com/about/versions/14/changes/fgs-types-required)

录音与核心交接流程：申请会话及暂存票据 → 原生收音并写入可恢复片段 → 封闭片段后幂等登记 → 停止时完成会话 → 核心发起后续处理。平台层在核心暂不可用时保留会话清单，恢复后补交。系统强制停止或进程终止后不能假装仍在录音，重开应显示实际可恢复范围。

Windows 需要验证设备切换、拔掉麦克风、系统休眠和关闭窗口的行为。正在录音时关闭窗口，应清楚让用户选择继续在后台记录或停止并保存；如果首版没有托盘能力，选择范围只能包含已实现的行为，不能出现无效的“后台继续”。

### 4.3 导入与系统入口

Android 支持系统文件选择、选图、拍照及分享接收。使用系统返回的受控 URI/句柄，按平台规则维持导入期间的访问，不要求用户授予整个存储目录权限。大文件以流式方式复制进应用管理的文件库。

Windows 支持文件选择、拖放、粘贴文字/截图。拖入多个文件时保留选择顺序，并允许部分失败。普通粘贴默认保留文字含义，不引入网页脚本或不可见控制内容。

平台层另提供按需准备视频音轨的接口，供后端调用转写流程；结果写入受控临时资产并保留原视频时间映射。不能可靠处理的编码明确返回不支持，视频原件仍可保存。媒体准备不在页面线程进行。

拍摄设备不可用时说明原因，保留文件选择方式。视频首版通过导入支持，直接录像不是首版必须入口。其他应用分享进来时，应能选择追加到当前草稿或保存为新记录，默认动作保持简单并允许撤销。

所有入口复用同一个记录及导入流程，不各自实现一套存储规则。

### 4.4 日记阅读页

正文按日期呈现，以自然段阅读为核心。不得把生成的日记默认排成要点、表格、带编号的总结。使用舒适行距、合理行宽和系统字体；Windows 大屏不能把正文拉成横跨整个窗口的一行。

原件以正文下方的材料条或可展开来源面板展示。点击来源可以打开文字、图片、文档或跳到音频时间点。来源关联不应让正文到处充斥技术编号。

当天没有正文但有材料时显示材料及“整理中/待配置/可以整理”。没有任何材料时呈现自然空白状态，不鼓励 AI 编造内容，也不以连续打卡中断制造压力。

如果仅使用部分材料生成，阅读页提供低干扰的“还有 2 项材料待处理”入口。不要把它显示成保存失败。候选新版本与当前阅读版分开，用户不选择时正文保持稳定。

### 4.5 编辑与版本

用户编辑以当前版本为基准。保存后生成新版本；返回阅读页仍可看到旧版本入口。重新生成不会覆盖正在编辑的文字。

对比视图至少支持并排或上下查看原版与候选版，并明确生成时间、生成/手动修改来源、材料覆盖变化。移动端以简单上下切换优先，避免过窄并排。

用户可以“采用这一版”“保留当前版”“编辑后保存为新版”。合并的第一版实现可以是用户可编辑的草稿合并界面，不要求先实现自动三方文本合并算法。若提供 AI 合并，必须另建候选版本并交由用户选择。

发生 revision_conflict 时保留未提交的输入，显示可恢复草稿；不清空编辑框，不自动选择最新版本覆盖。

### 4.6 搜索页

统一搜索框，默认混合检索。日期、材料类型、原始资料/日记范围作为简洁筛选，允许关闭筛选。中文输入法组合输入未提交前不要连续发起查询。

建议在输入稳定约 250 毫秒后搜索，取消过时请求。关键词结果可以先出现；语义补充完成后保持已展示结果的阅读位置，不让整个列表频繁跳动。新查询结果只接受匹配的 sessionId/queryRevision。

每项结果显示能够理解的日期、片段及来源类型。录音结果有直接播放片段入口；文档可定位页码；照片显示缩略图；同一记录的多种命中聚合，避免同一内容重复占满列表。

默认折叠旧版本，但提供“包括历史版本”。没有命中与有内容未处理是两个不同状态。向量模型暂未就绪时显示关键词结果和简洁状态，不阻塞整个搜索页面。

不要把相似度显示成“准确率 93%”。可以用“内容相关”“原文匹配”等来源标记帮助理解，但不强迫用户理解检索算法。

### 4.7 模型、风格与任务设置

模型设置先让用户选预设或自定义服务，再填写必要字段。测试连接显示支持哪些能力；不能仅凭成功返回一个模型列表就声称语音转写和图片理解也可用。尚未配置时仍能记录、离线搜索已有可解析文本。

密钥输入有遮挡，默认不回显；敏感内容不进入错误截图或诊断日志。使用范围与可能发送的材料类型在首次配置时说明。后续在已授权范围内自动处理，不逐条反复弹确认。

风格设置用易懂的选项和可选示例表达，例如篇幅、克制/温暖、第一人称/旁观叙述。默认值需符合简洁、有感染力和自然段正文。不要给用户堆满温度、token 等参数。

任务中心按“处理中、等待、需要处理、完成”聚合。后台临时网络故障只在状态区体现；持续认证失败等需要用户操作的情况才适当提示。使用核心返回的 attentionKey 并确认已展示状态，实现跨重启通知去重，避免同一失败反复打扰。

### 4.8 插件、备份与存储

插件详情显示功能、作者、版本、平台支持和所需权限。检查包不能执行包内容。用户安装并授权后才启用；增加权限的更新重新展示变化。停用/卸载后保留已有日记和原件。

备份页面明确区分“可恢复备份”和“导出阅读文档”。展示包含内容、空间需求、目标位置与是否加密。恢复先预览检查结果，默认新建库，避免直接覆盖现有资料。

存储页显示原件、缓存、索引、备份的占用。清理缓存不能删除原件。永久删除前使用核心返回的影响预览，说明生成日记中可能仍保留相关文字。

## 6. 前端测试重点

组件测试聚焦会丢数据或造成误操作的状态：保存确认、版本冲突、录音中断、旧搜索结果覆盖、附件部分失败、键盘提交。无需为纯装饰样式写镜像实现的测试。

必须做真实设备端到端测试：断网启动并记录、三十分钟以上录音、锁屏/切后台、取消大文件导入、混合搜索后定位原件、生成期间编辑、恢复备份。完整案例见验收计划。

视觉检查覆盖 Android 小屏和 Windows 窄/宽窗口、深浅色、系统字体放大、中文长文本与中英文混排。录音状态不能仅用颜色表达，关键按钮要有可访问名称。

## 7. 完成定义与交接

前端每阶段提交：已完成页面及真实/Mock 接入状态、改动目录、使用的接口版本、运行步骤、测试结果、平台限制和待后端处理事项。不得只交截图、静态页面或只有成功路径的 Mock。

任何契约缺口先提交明确请求：缺少的方法/字段、触发场景、建议语义、对现有调用的影响。不要在页面里偷偷访问数据库弥补缺口。

最终由前端层任务负责应用外壳的组装和安装包打包；后端层必须提供可链接产物、生成流程、依赖及资源清单。打包遇到核心问题交还给认领后端层任务的人修复，不复制核心代码到 UI 中。
