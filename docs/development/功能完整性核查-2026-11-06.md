# 功能完整性核查（2026-11-06）

判定口径：**核心实现 → 桥接（frb）→ 契约（diary_api）→ 界面**，四层都通才算「可用」。

## 一、可用（四层都通，且真机验证过）

| 功能 | 说明 |
|---|---|
| 记录 / 编辑 / 收好这一刻 | captures.*，含草稿保存、日期切换 |
| 说大话（全屏写作） | 与普通模式共用同一条记录 |
| 文件导入 | imports 流程 + 恢复日志 |
| 搜索（关键词） | search.start / nextPage |
| 片段时间线 | captures.list |
| 日记整理 | diary.generate + jobs.runDue，真机用 DeepSeek 跑通过 |
| 日记版本 | listVersions / getVersion / saveEdit / setCurrent |
| 模型服务 | 在线 + 本机，含密钥、连接测试、模型列表 |
| 风格偏好 | styles.save，进提示词 |
| 整理时机 | organize settings + 模板 |
| 任务中心 | jobs.list / retry / cancel |
| 备份与恢复 | backups.create / inspect / restore |
| 存储与回收站 | trash / restore / previewPurge / purge |
| 阅读导出 | exports.create |

## 二、核心已实现、桥已接、契约有，**但界面还是占位**

这两处是最大的缺口——后端全通，用户点不到。

| 功能 | 核心 | 桥 | 契约 | 界面 |
|---|---|---|---|---|
| **录音** | ✅ recordings::prepare/register/finalize/recover | ✅ | ✅ | ❌ 点「录音」只弹一句「录音正在接入」 |
| **插件** | ✅ plugin::install/list/run/enable | ✅ | ✅ | ❌ 面板写着「插件还没接上，下面的开关是预览」 |

## 三、契约有、界面是演示

| 功能 | 现状 |
|---|---|
| 主动回应（requestResponse） | 面板写着「演示不会调用 AI」，实际没接 |
| 来源定位（locateSource） | 无界面 |
| 资产打开/释放（openAsset/releaseAsset） | 无界面（录音播放要用） |
| 日记列表（listDays） | 无界面（没有「所有日记」列表 / 日历） |

## 四、契约有、界面没有

| 功能 | 说明 |
|---|---|
| 版本合并（`mergeDiary`） | 契约 `diary_api.dart:263` 有，核心与桥都通，**界面没有入口** |
| 日记列表（`listDays`） | 同上：没有「所有日记」列表或日历视图 |

## 五、核心有、桥有、**契约没有**

| 功能 | 说明 |
|---|---|
| 选择生成服务（`providers.selectGeneration`） | 核心与桥都有；Dart 契约没有。多个服务时**无法指定用哪个**——现在按顺序取第一个测通的 |

## 六、平台限制（不是缺陷）

| 功能 | 说明 |
|---|---|
| 语义检索 | Windows 包不含本地模型，需自配模型目录；不会自动下载 |
| 录音转写 | 同上，需要 sherpa-onnx 模型 |

## 七、结论

- **能用的**：记录 → 整理 → 版本 → 备份 → 导出，主链路完整。
- **最大缺口**：录音、插件——**后端都好了，只是没人做界面**。
- **次要缺口**：主动回应、来源定位、资产播放、日记列表、版本合并、指定生成服务。

### 复核时纠正的两处

1. 我一开始把「版本合并」写成「契约没有」——那是搜了桥里的名字 `mergeDiaryVersions`。
   契约里叫 `mergeDiary`，**有**。结论改成「契约有、界面没有」。
2. `listDays` 同理：契约有，界面没用。
