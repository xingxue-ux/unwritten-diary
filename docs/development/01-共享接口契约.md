# 共享接口契约 v1

本文件是两层共同依据，也是唯一的同步点。方法名是设计标识，不是已经存在的实现。

**状态：v1 已冻结（2026-09-27）**。冻结之后，新增字段、方法或改变语义都必须先更新本文件（或先提「契约变更请求」issue），再改实现；先改实现再补文档的 PR 不予合并。`packages/diary_api` 类型包与 Mock 实现都必须符合本文件，目录与流程见 [CONTRIBUTING.md](../../CONTRIBUTING.md)。

## 1. 调用与数据约定

### 1.1 两条独立接口

DiaryApi 是 Flutter 到本地业务核心的异步接口，涵盖资料、日记、搜索、任务与设置。PlatformHost 是系统能力接口，负责录音、播放、选文件、权限、系统凭据和后台唤醒。页面依赖抽象接口，不直接调用数据库、Rust 内部对象或某个模型服务的 HTTP API。

实际产品使用 RustBridgeDiaryApi；页面测试使用 MockDiaryApi。两者必须实现同一组方法、错误和事件语义。

### 1.2 基本规则

| 项目 | 契约 |
|---|---|
| 标识 | 不透明字符串 ID，不让前端解析或拼接；由核心生成 |
| 时间 | UTC 时间以带 Z 的 ISO 8601 表达；另存 IANA 时区和当时偏移 |
| 日归属 | dayKey 为 YYYY-MM-DD，按设置的 diaryTimeZone 计算；导入时间与事件时间分开 |
| 修改时区 | 只影响新材料的默认归属；不静默搬动历史日记；历史调整走明确操作 |
| 文本区间 | Unicode 标量值计数，左闭右开；前端在 Dart 中转换为实际字符串下标，不直接当 UTF-16 下标 |
| 音视频位置 | 从逻辑媒体开始的毫秒数，暂停间隔不计入播放时间；原始墙钟时间另存 |
| 页码 | 从 1 开始；无法可靠定位页码时返回空，不伪造 |
| 分页 | 不透明 cursor，默认 20 条，最大 100 条；确定性排序包含 ID 作为并列次序 |
| 大数据 | 音视频、原图、整库数据不通过一次桥接调用整体传输；使用分页、范围读取、受控文件句柄 |
| 修改并发 | 带 expectedRevision；不匹配返回 revision_conflict，不静默覆盖 |
| 幂等 | 可重试写入带 operationId；先查已完成操作再检查 revision；同一操作重试返回原结果；同一 ID 配不同内容报冲突 |
| 取消 | 长任务返回 jobId/searchSessionId；取消停止后续处理，不删除已经保存的原件 |
| 错误 | code、用户可读 message、retryable、可选 jobId/fieldErrors；堆栈只进入脱敏诊断 |
| 持久化确认 | 只有核心完成持久化后才返回 durable=true；UI 的“已保存”以此为准 |

建议初始默认：diaryTimeZone 为首次设置时的设备时区，可修改；自动整理 22:30；跨午夜长录音归入开始录音时的 dayKey。用户可以明确调整归属日期，调整不改录音时间戳。

### 1.3 协议版本

CoreInfo 返回 apiVersion、dataSchemaVersion、buildVersion、支持能力和当前库 ID。apiVersion 使用主次版本；新增可选字段为次版本，删除或改变语义为主版本。UI 与核心主版本不兼容时进入恢复/更新页面，不继续写入。

- 第 3 节状态机的状态名与流转规则。
- 第 4、5 节的方法名、输入与输出保证。

## 2. 主要数据对象

### 2.1 Capture：一次记录

Capture 表示用户的一次混合记录，可以同时包含文字、照片、录音和文件。

| 字段 | 含义 |
|---|---|
| id / revision | 标识及乐观锁版本。**新建记录的 `revision` 从 1 开始**，此后每次成功写入 +1（保存草稿、提交、改文字各算一次）；`expectedRevision` 必须等于当前值，否则 `revision_conflict` |
| state | draft、committed、trashed |
| occurredAt / createdAt / updatedAt | 事件时间、入库时间、最后修改时间 |
| timeZone / utcOffsetMinutes / dayKey | 时间语义与日记归属 |
| orderedSourceIds | 按展示顺序组织的文字或附件来源 |
| draftText | 草稿正文，仅 draft 阶段可直接变更 |
| processingSummary | 未处理、处理中、可检索、需关注的数量 |

草稿频繁保存只更新当前草稿与恢复日志，不为每个按键制造永久版本。提交时创建原始文字版本。提交后修改文字则创建新的 SourceRevision，旧版本保留。

### 2.2 SourceItem / SourceRevision：原始内容

| 字段 | 含义 |
|---|---|
| sourceId / captureId | 稳定来源标识及所属记录 |
| kind | text、image、audio、video、file、link |
| currentRevisionId | 当前原始文字或来源元数据版本 |
| revisionId / parentRevisionId | 本次原始内容修订及父版本 |
| text / assetId | 文字原件或文件库中的资产引用 |
| authorType | user、import；AI 生成正文不写成 user 来源 |
| occurredAt / provenance | 时间及来源信息，导入附带的元数据不得冒充已确认事实 |

已保存原件不能被模型或插件覆盖。用户明确删除是另一条操作，不与自动清理缓存混淆。链接本身先保存；网页抓取需要相应能力，抓取失败不丢失链接和备注。

### 2.3 Asset：文件库资产

| 字段 | 含义 |
|---|---|
| id / objectRef | 稳定 ID 和核心管理的内部文件引用 |
| originalName / detectedMime / byteSize / sha256 | 文件信息及完整性校验 |
| mediaDurationMs / width / height | 可选媒体属性 |
| storageState | importing、ready、recoverable、missing、trashed |
| importOrigin | picker、camera、paste、drop、share、recording、restore |
| createdAt | 本地入库时间 |

原始外部路径或 Android content URI 不作为长期资产地址。用户删掉下载目录中的原文件后，已成功导入的材料仍可打开。objectRef 不是供插件任意访问的系统路径。

### 2.4 ExtractedContent / SourceLocator

ExtractedContent 含 id、sourceId、sourceRevisionId、extractorId、extractorVersion、text、segments、status、coverage、errorCode。它是可重建的派生内容，与原件分开。

SourceLocator 含 type 与对应字段：text_range 使用 start/end；audio/video 使用 startMs/endMs；document 使用 pageNumber 和可选 blockId；image 使用可选归一化矩形；file 使用 assetId。每个 locator 必须携带 sourceRevisionId，保证定位到当时的原文版本。

coverage 要能表达 complete、partial、metadata_only、unavailable，以及用户可读原因。图片描述属于机器提取，不自动变成用户亲口表达的感受。

### 2.5 DiaryDay / DiaryVersion / StyleProfile

DiaryDay 含 dayKey、timeZone、currentVersionId、candidateVersionIds、materialCounts、coverage、updatedAt。

DiaryVersion 含 id、dayKey、parentVersionId、origin（generated、user_edit、merge）、body、createdAt、sourceSnapshotId、styleSnapshotId、generationInfo、provenanceLinks。body 是自然段正文；来源关联放在独立字段，阅读页不把正文变成报告。

sourceSnapshotId 对应不可变的输入清单：来源 ID、修订 ID、已使用提取版本及未处理项。provenanceLinks 以段落或内容范围关联原件；不要求每一句抒情修辞都有机械式引用，但涉及事实的内容要能追溯。

StyleProfile 含长度偏好、叙述人称、语气、情绪温度、允许的修辞程度、可选示例和明确禁用表达。偏好变更不自动重写历史日记。风格默认只从用户明确设置和确认后的修改中调整；自动推断出的偏好应作为建议，不能悄悄固化。

### 2.6 SearchRequest / SearchHit / SearchSnapshot

SearchRequest：query、mode（keyword、semantic、hybrid）、filters、pageSize。filters 包括日期范围、材料类型、来源范围、是否包含旧日记版本；默认 hybrid、排除回收站、折叠历史版本。

SearchHit：hitId、groupId、sourceKind、sourceId、revisionId、dayKey、title、snippet、highlights、locator、matchedBy、coverage。matchedBy 为 keyword、semantic、metadata 中的一个或多个，不把向量相似度显示为事实置信度。

SearchSnapshot：sessionId、queryRevision、phase（initial、keyword_ready、hybrid_ready、done、cancelled）、results、cursor、indexCoverage、warnings。每次事件发送当前页的完整快照，前端按 hitId 更新；不得把两份完整快照当增量直接拼接。

旧查询的结果不能覆盖新查询。核心返回 queryRevision，前端同时校验当前 sessionId 与 queryRevision。翻页绑定原会话；索引变化造成快照失效时返回 search_expired，让前端重新开始。

### 2.7 Job / Provider / Plugin

Job：id、kind、state、targetIds、inputSnapshotHash、progress（可空）、createdAt、updatedAt、attemptCount、nextAttemptAt、errorCode、requiresUserAction、attentionKey。attentionKey 表示同一个需处理问题，用于跨重启去重通知。没有可靠进度时 progress 为空，不能虚构百分比。

Provider：id、label、endpoint、adapterId、model、capabilities、credentialRef、enabled、testStatus。capabilities 至少区分 generate_text、transcribe_audio、understand_image；本地 embedding 属于独立配置。API 返回凭据存在与否，不返回密钥明文。

Plugin：id、version、apiRange、supportedPlatforms、activationEvents、requestedPermissions、grantedPermissions、entryKind、state、lastError。模型提供者插件可请求核心代为调用已配置服务，普通处理插件不直接得到所有模型密钥。

## 3. 状态机

| 对象 | 状态流转与规则 |
|---|---|
| 草稿 | draft → committed；draft/committed → trashed；恢复回原状态 |
| 导入 | prepared → copying → verifying → ready；中断为 recoverable；失败明确 error，不提前宣称原件完整保存 |
| 录音 | idle → preparing → recording ↔ paused → stopping → saved；可进入 interrupted/recoverable/error |
| 任务 | queued → running → succeeded；可进入 retry_wait、waiting_configuration、waiting_dependency、waiting_network、failed、cancelled |
| 索引 | pending → processing → ready；可为 partial/failed/stale，按材料和模型版本维护 |
| 日记 | 首次生成可成为 current；后续生成默认 candidate；用户选择后成为 current；旧版本仍保留 |
| 插件 | installed → disabled/enabled；被触发才 running；出错回 enabled 或 quarantined，不影响原件存储 |

中断与失败不是同义词。来电中断显示“录音已暂停/中断”，不得继续显示正在收音。任务等待用户配置时不自动无限重试。

## 4. DiaryApi 方法清单

### 4.1 核心、记录与来源

| 方法 | 输入 | 输出及保证 |
|---|---|---|
| core.open | libraryHandle 可空 | CoreInfo + 恢复摘要；空值打开/创建默认库；只初始化记录必要能力 |
| core.snapshot | 需要的范围 | 轻量启动快照，不返回整库正文或媒体 |
| core.close | 当前会话 | 完成必要提交；不等待远端模型任务完成 |
| core.setRuntimeState | 前后台、录音活跃、内存/电量压力 | 更新资源调度建议，不修改原件 |
| captures.createDraft | occurredAt 可选、operationId | Capture |
| captures.saveDraft | id、text、expectedRevision、operationId | 新 revision、durable 标记、savedAt |
| captures.commit | id、expectedRevision、operationId | Capture + 原始文字版本；附件未完成时保留其真实状态 |
| captures.get / list | id 或日期/cursor | 详情或分页摘要 |
| sources.reviseText | sourceId、text、expectedRevision、operationId | 新 SourceRevision，不覆盖旧内容 |
| captures.moveDay | id、目标 dayKey、expectedRevision | 更新归属；标记相关日记候选需更新 |
| captures.trash / restore | id、expectedRevision、operationId | 状态；索引可见性同步变更 |
| captures.previewPurge | id | 将删除的原件、派生内容及仍引用它的日记版本清单 |
| captures.purge | id、previewToken、operationId | 永久清理结果；只由明确的用户操作发起 |

### 4.2 文件与录音交接

| 方法 | 输入 | 输出及保证 |
|---|---|---|
| imports.prepare | captureId、displayName、mimeHint、sizeHint、operationId | importId、限域 stagingTicket |
| imports.finish | importId、ticket、复制完成信息 | 接收校验任务；ready 后才视为完整文件入库 |
| imports.status / cancel | importId | 实际状态；取消不删除其他已导入材料 |
| recordings.prepare | captureId、格式偏好、operationId | recordingId、assetId、限域暂存目录票据 |
| recordings.registerSegment | recordingId、segmentId、相对文件名、时长、校验、序号 | 幂等接收结果；已封闭片段的持久化确认 |
| recordings.updateState | recordingId、原生状态、墙钟时间、durableThroughMs | 会话快照；后端不虚构麦克风状态 |
| recordings.finalize | recordingId、最后片段序号、结束原因 | 最终化状态、逻辑音频 Asset；转写不阻塞完成 |
| recordings.recover | recordingId 或暂存清单 | 可恢复片段、缺口信息和新的会话状态 |
| assets.open | assetId、用途 preview/play/export | 只读句柄或限域租约；不把任意路径开放给插件 |
| assets.release | leaseId | 释放句柄/临时文件 |
| sources.locate | sourceRef、locator | 前端可打开的原件、定位信息、来源可用性 |

PlatformHost 只在明确的 stagingTicket 范围内写入。原生录音需要维护追加式会话清单和封闭片段，即使 Flutter UI 销毁也能继续或恢复。建议片段封闭/检查点间隔不超过 5 秒，实际格式与频率在 M0 根据音质、空间和恢复结果冻结。

片段按单调序号组织；暂停后的继续仍属于同一逻辑录音。前端按逻辑播放时间定位，后端/平台层负责映射到具体片段。不能要求一次性拼接整段长音频到内存。

### 4.3 日记、版本、回应

| 方法 | 输入 | 输出及保证 |
|---|---|---|
| diary.getDay / listDays | dayKey 或范围/cursor | DiaryDay 与需要的正文摘要 |
| diary.generate | dayKey、styleId、生成原因、operationId | jobId、sourceSnapshotId；冻结输入后处理 |
| diary.listVersions / getVersion | dayKey 或 versionId | 分页版本/完整版本 |
| diary.saveEdit | baseVersionId、body、expectedRevision、operationId | 新 user_edit 版本，不覆盖基版 |
| diary.setCurrent | dayKey、versionId、expectedRevision | 当前版本更新 |
| diary.merge | baseVersionId、候选版本、用户确认后的正文 | 新 merge 版本，保留两个来源版本 |
| styles.get / save | profile 或范围 | StyleProfile；每次生成使用风格快照 |
| responses.request | captureIds、用户请求文字、providerId 可选 | jobId；只有主动调用才运行 |
| responses.get | responseId | 独立回应对象，带来源和生成信息 |

AI 回应不自动成为日记的原始事实。用户可把它标记为“保留的 AI 回应”，但必须保留生成来源。

| 方法 | 输入 | 输出及保证 |
|---|---|---|

| indexes.status | 可选来源范围 | 内容覆盖、模型版本、未处理原因 |

| jobs.list / get | 筛选/cursor 或 id | 持久任务状态 |

## 5. PlatformHost 方法与所有权

| 系统能力 | 负责方 | 交接规则 |
|---|---|---|
| 权限查询/申请 | 前端平台层 | 返回 granted/denied/restricted；用户拒绝时其他记录方式继续可用 |
| start/pause/resume/stopRecording | 前端平台层 | 首个有效音频缓冲后发 recording；不能由按钮点击直接推定 |
| 录音状态订阅 | 前端平台层 | 含真实状态、已录时长、已持久化位置、输入设备变化 |
| 选择/拍摄/分享/粘贴/拖入 | 前端平台层 | 输出短期句柄，流式复制到 imports.prepare 提供的位置 |
| 播放及跳转 | 前端平台层 | 依据 core 提供的逻辑媒体与定位信息播放 |
| 视频音轨准备 | 前端平台层 | 按需将指定视频音轨导出到受控临时资产，保留时间映射；不支持的编码如实返回 |
| 凭据存储与读取 | 前端平台层，核心受控调用 | 使用系统能力；缺失或锁定时任务进入 waiting_configuration |
| 后台唤醒注册 | 前端平台层 | 向系统登记任务；唤醒后调用核心处理到期任务 |
| 平台生命周期 | 前端平台层 | 报告前后台、电源及内存压力，核心据此调整任务预算 |

M0 必须验证 Android 后台工作如何进入核心：可通过受控无界面运行入口，不能依赖某个页面对象存在。具体桥接路径在架构决定中固定。录音保存路径必须在无 Flutter UI 的情况下仍可工作。

初始化桥接时注册 PlatformHostBridge，暴露受控文件票据、凭据读取、媒体准备和系统状态等能力；测试以 FakePlatformHost 实现。调用不得经过 Widget，宿主不可用时返回明确错误或等待状态。录音状态与后台任务预算由宿主提供，核心不自行假定系统能力已获授权。

## 6. 事件与恢复

持久业务事件至少包含 eventId、sequence、type、entityId、revision、emittedAt。类型包括 capture.changed、asset.changed、diary.versionCreated、diary.currentChanged、job.changed、index.coverageChanged、plugin.changed。

前端从快照开始订阅，按 revision 去重。断线或进程恢复后先获取快照，再从可用游标补事件。事件游标过期返回 cursor_expired，前端重新读快照，不能无限等待遗漏事件。

搜索结果、音量波形和实时录音计时属于临时事件，不承诺历史回放。录音真实状态可由原生服务重新查询；搜索恢复时重新发起查询。高频波形不写数据库，不淹没业务事件队列。

## 7. 错误码与用户行为

| 错误码 | 用户界面行为 | 自动行为 |
|---|---|---|
| storage_full | 明确显示未保存/录音停止，提供空间信息 | 停止继续写入，保留已封闭片段 |
| permission_denied | 说明对应权限，保留文字等入口 | 不循环弹权限框 |
| revision_conflict | 展示当前版和用户待保存内容 | 不覆盖；用户内容保留在恢复草稿 |
| idempotency_conflict | 保留待保存输入，提示操作状态冲突 | 不复用旧结果覆盖不同输入 |
| not_found | 说明目标已不存在（例如已被清理），回到列表 | 不创建新记录，也不静默当作成功 |
| invalid_state | 说明当前状态不允许这个操作，显示真实状态 | 不改数据；提示刷新后重试 |
| asset_missing | 显示文件暂不可用与来源信息 | 不把无文件资产当作可播放 |
| integrity_failed | 说明这份材料没有完整保存，提供重试或取消入口 | 保留暂存文件；不创建资产，也不提前宣称已保存 |
| unsupported_format | 仍保留附件，注明仅文件信息可搜 | 不无限重试解析 |
| provider_not_configured / authentication_failed | 设置页和任务中心提示 | 等待配置，不频繁重试 |
| network_unavailable | 材料已保存，处理待联网 | 有退避地排队 |
| rate_limited / quota_exceeded | 提供简洁状态和手动处理入口 | 尊重 Retry-After；额度问题暂停 |
| provider_timeout | 显示本次整理未完成 | 有限重试；不承诺远端未计费 |
| model_unavailable | 关键词搜索仍可用，语义搜索状态可见 | 检查包及版本，恢复后补索引 |
| plugin_denied / plugin_budget_exceeded | 显示插件未完成，可停用 | 终止该调用，不连带中断记录 |
| incompatible_backup / corrupted_backup | 恢复失败原因清晰 | 不修改现有库 |
| search_expired / cursor_expired | 安静刷新当前范围 | 丢弃旧会话结果并重取 |

## 8. 删除、版本、备份与派生数据

回收站内容立即从默认搜索和后续 AI 输入中排除。恢复后重建必要索引。永久删除需要预览结果：原文件、提取内容、切片及向量一起清理；已存在的日记正文可能仍包含当时的信息，必须单独列出，让用户决定是否同时删除关联日记版本。

默认备份包含原件、原始文字版本、日记版本、风格、关系与必要元数据。索引和缓存可选，API 密钥、运行中会话、临时凭据不进入备份。首版基础备份是用户明确导出的普通归档包，界面明确标注含私人资料；不宣称已加密。加密备份可后续单独实现。

恢复先检验格式、版本、哈希、大小及安全路径，再导入新资料库；索引可后台重建。普通资料导出与可完整恢复的备份要有不同名称和入口。
