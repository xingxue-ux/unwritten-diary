# 鸿蒙 LLM 配置与打包交接

**2026-10-25（本版起）：日记生成需要一个在线模型服务。**

安装包不再内置 Qwen3.5-0.8B / llama.cpp，也没有「本机整理」这个选项。
全新安装或升级后，第一次生成日记之前必须在「我的 → 模型服务」里添加一个在线服务、
检查连接，然后点「使用此服务」。没有可用服务时，日记页点「整理这一天」会直接显示
「整理日记需要一个在线模型服务」并给出「去配置模型服务」按钮——不会排一条空等配置的任务，
也不会只丢一个 `provider_not_configured` 技术错误码。

语音转写（SenseVoice）与语义检索（BGE）仍是随包本地能力，不需要配置、不需要联网，
和日记生成互不影响。随包模型与体积见 [鸿蒙随包本地模型](product/鸿蒙随包本地模型.md)。

**升级行为**：旧的 `bundled-models/v1/llm/` 权重（约 563 MB）会被回收；用户自己
配置的在线服务、密钥、连接测试结论与日记都保留。旧版本自动种下的
`builtin_local_llm`（`adapter_id = llama_cpp`）配置行**不会被静默删除**：
它列在「模型服务」页的「旧版本留下的配置 / 已不再支持」里，说明为什么不能用，
由用户自己决定删不删。升级后如果从来没有配过在线服务，整理能力在配好之前不可用
——这是本次**有意的功能回退**，版本号因此升到 1.0.3 / 1000003。

老库里这条旧配置的所有入口都如实说明、不会崩：`providers.list` 照常列出；
`providers.selectGeneration` / `providers.test` 明确拒绝并提示改用在线服务；
`diary.generate` 的任务停在 `waiting_configuration`（`requires_user_action`，
不消耗尝试次数、不写空正文），`diary.getDay` 照常可读。

「我的 → 模型服务」在**在线服务之间**选一个：卡片上的「使用此服务」或编辑区的
「使用此服务」。切换原子完成，其他整理服务停用，已保存的配置、密钥与连接测试结论保留。
查询模型列表实时向服务端请求。已知模型显示中文简称及原始编号，新模型直接显示服务返回的原始名称，
避免猜测或混淆；请求始终使用原始编号。`providers.selectGeneration` 的语义是
「在一个**已启用、声明 generate_text、且适配器真的实现了 generate_text 的在线服务**里选一个」；
本机引擎（`sherpa_onnx`）不会被选中。

2026-10-24 已完成原签名打包与真机 DeepSeek 联调。首次使用中发现的配置状态、表单误判、反馈位置和索引入口问题已修复；最新结果见 [首次使用验收](product/鸿蒙首次使用验收-20261024.md)。下文最初提交时的验证与交接保留为历史记录。

## 用户操作

入口为「我的 → 模型服务」，日记页也有「配置 AI 模型服务」入口。语音转文字仍在独立的「本地语音转写」页面。

0. 页面上没有「本机」选项：日记生成只由在线服务承担。
1. 添加自定义服务，或使用核心提供的预设填表。预设只提供参考值，不代表已联网验证。
2. 填写名称、API 根地址和 API Key。支持 `openai_compatible` 协议。地址不要附带 `/chat/completions`、`/models`、账号密码或查询参数。
3. 保存配置。新服务及编辑后的服务均处于停用状态，保存本身不会探测远程服务。
4. 若不知道模型 ID，可以先不填模型，保存后点击「检测可用模型」。点选返回的模型，再保存；服务不支持列举时可按服务商说明手填。
5. 点击「测试文本生成连接」。会发送测试文字并可能计费，不包含用户日记。测试结论从核心重新读取，不由界面伪造。
6. 测试通过后点击「使用此服务」，也可直接在服务卡片上切换。随后到日记页生成；没有可用服务时日记页会引导回本页配置。

远端地址使用 HTTPS。只有设备自身的 localhost / 127.* / [::1] 允许 HTTP；手机上的 localhost 并不指开发电脑。局域网服务请配置有效 HTTPS 和所需凭据。

多个在线服务可以分别保存，每次只选择一个整理服务。切换使用 `providers.selectGeneration`，不额外测试连接或联网；已排任务仍遵循原有来源冻结规则。本机转写配置不参与这个选择。

## 凭据语义

- 编辑时 API Key 留空表示保留已有 `credential_ref`，不会清除旧密钥。
- 输入新值会替换密钥；保存提交后与离页时清空界面的密钥输入，不再回填明文。
- 删除服务需要确认，核心清理不再被使用的凭据；不删除日记。
- 使用核心现有 `providers.save(config, secret)` 和 `SecretStore`。目前默认存储是应用沙箱下的独立受限文件，**未接入 HUKS/系统密钥库，也不宣称硬件加密**。不要把真实 API Key 写进预设、代码或 PR。
- 打开页面、读取预设、保存表单不探测网络；列模型与测试由用户分别点击。启用后已有调度流程可能领取用户之前提交的任务。

## 最初提交时的实现与验证

`LlmConfigPage.ets` 通过既有 TaskPool 网关调用 `providers.list/presets/save/models/test/remove`，不在 UI 线程运行网络/SQLite。任务中心的 respond / diary_generate / organize 配置入口跳转至此，transcribe 仍跳本地转写。

2026-10-23 本机验证（历史，适用 1.0.2 及更早；当时页面还有「本机整理」选项）：

- 六组主机交互回归通过，新增场景覆盖：保存不联网、保留/替换密钥、编辑后禁用测试、测试前禁止启用、测试后启用、状态读取失败时阻止操作、失败保存清空密钥、放弃修改确认、地址校验。
- 32 个非 UI ArkTS 文件的 TypeScript 5 语法与作用域检查通过。
- 使用本机 DevEco SDK 完成 debug `assembleHap`，包含完整 ArkTS 页面编译及未签名打包；存在旧 API 弃用与设备能力警告，无编译错误。
- **未签名包不是可交付产品包**：本机没有原签名及产品原生引擎库，没有做真实服务计费调用、重启后凭据验证或修复版真机验收。

分支 `feat/ohos-llm-settings-20261023` 基于 #203 的 `fix/ohos-audit-20261023`，因此同时含前次六项修复、小猫图标和 INTERNET 权限。

请在原签名电脑检出该分支，沿用产品原生库构建流程、原 bundleName 和原签名，构建 signed HAP 后覆盖安装；不要使用本机缺少产品原生库的验证包，不要卸载清库。
